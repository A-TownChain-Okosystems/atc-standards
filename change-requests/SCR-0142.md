## 1. Entscheidung

Elf bestehende Spezifikations-IDs werden in die Registry aufgenommen, ohne ihren Inhalt, ihren Status oder ihre Version zu verändern:

| ID | Gegenstand (Ist-Stand der Quelle) | Quell-Repository |
|---|---|---|
| ATC-COMP-500 | Compute Architecture Specification | `atc-compute` |
| ATC-COMP-501 | Job Specification | `atc-compute` |
| ATC-COMP-502 | Scheduler Specification | `atc-compute` |
| ATC-COMP-503 | Worker Specification | `atc-compute` |
| ATC-COMP-504 | Resource Metering Specification | `atc-compute` |
| ATC-COMP-505 | Attestation Specification | `atc-compute` |
| ATC-COMP-506 | Verification Specification | `atc-compute` |
| ATC-COMP-507 | Determinism Specification | `atc-compute` |
| ATC-COMP-508 | Security Specification | `atc-compute` |
| ATC-COMP-509 | Economics Specification | `atc-compute` |
| ATC-CRYPTO-001 | Cryptographic Specification (Primitive, Domain-Separation, PQC-Pfad) | `a-townchain` |

**Korrektur, die zur Entscheidung gehört:** die im Owner-Text vom 15.11.2026 verwendete Zuordnung war um eine Position verschoben. Nicht 500 ist das Job-Schema, sondern 500 ist die Architektur, 501 das Job-Schema, 502 der Scheduler, 503 der Worker, 504 die Ressourcenmessung, 505 die Attestation, 506 die Verifikation, 507 der Determinismus, 508 das Threat-Model, 509 die Ökonomie. Die Registrierung folgt dem Ist-Stand der Dateien, nicht der verschobenen Liste, weil eine Registrierung die Quelle nicht umbenennen darf.

**Registrierung ist nicht normative Freigabe.** Daraus folgt ausdrücklich: kein Eintrag ist `candidate` oder `approved`, keiner ist normativ, keiner erhält Implementierungs- oder CI-Status. Alle elf stehen in der Implementierungsmatrix als `specification_only`.

## 3. Prüfung ATC-CRYPTO-001 (Auflage des Owners)

Die ID wird an zwei Stellen normativ vorausgesetzt: ATC-COMP-505 REQ-ATT-004 (Domain-Separation, Tag `atc-compute.attestation.v1`) und ATC-STD-018 §PQC-Migration. Befund:

- Dokument vorhanden: `a-townchain/specs/ATC-CRYPTO-001-CRYPTOGRAPHY.md`, Version `0.1.0-DRAFT`, Status `SPEC-DRAFT`, `Implementierung PENDING` (Selbstauskunft der Datei).
- Die Datei behauptet keinen funktionierenden Zustand. Primitive sind im Ökosystem teilweise in Gebrauch (`sha2` in `a-townchain/components/node`, siehe `AUDIT-O1-C-HASH-CALLS-2026-11-15.md`), das ist jedoch keine Spezifikationskonformität und erzeugt keinen Implementierungsstatus.
- Folge für den Compute-Standard: die Domain-Separation der Attestation bleibt bis zum Spec-Freeze von ATC-CRYPTO-001 ungesichert. Das ist als offener Punkt geführt, nicht als erledigt.

## 4. Was ausdrücklich NICHT umgesetzt ist

- Profil `atc-compute`: `domain_extension` bleibt `pending`. Geschlossen wird erst, wenn alle Registry-Anforderungen erfüllt sind.
- Kein Dachstandard, keine ID `ATC-STD-COMPUTE-001`. Der Entwurf bleibt Arbeitspapier.
- Keine Änderung an `atc-mining` (O-C2 offen), keine Hardwareklassen-Erweiterung im Kernel (O-C3 offen).
- Keine Implementierung, kein Test, kein CI-Nachweis für die Spezifikationen selbst.

## 5. Nachweisbedarf

Ein grüner Lauf allein ist keine Abnahme (Owner-Auflage). Erforderlich ist ein auf den exakten Commit gebundener Lauf der Gates `cross-registry` (R1 bis R15), `allocation-gate`, `version-gate`, `regenerate-views` und des Repository-Audits, mit Run-ID und Commit-SHA. Bis dahin bleibt der Vorgang IMPLEMENTED im Schreibsinn, nicht VERIFIED.
