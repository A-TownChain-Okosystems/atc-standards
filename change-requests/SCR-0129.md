# SCR-0129 — A-TownChain Monetary Type Policy

## 1. Vorgeschlagener kanonischer Monetary Standard

- maximale Supply: **360,000,000 ATC**
- Dezimalstellen: **18**
- Base Unit: **10^-18 ATC**
- 1 ATC = 1,000,000,000,000,000,000 Base Units
- 1 Base Unit = 0.000000000000000001 ATC
- wirtschaftliche Ganzzahlrepräsentation: **u128**

Kanonische wirtschaftliche Werte:

| Wert | Typ |
|---|---|
| amount | u128 |
| balance | u128 |
| supply | u128 |
| stake | u128 |
| reward | u128 |
| slashing | u128 |
| treasury | u128 |

Protokoll-/Technikwerte bleiben semantisch getrennt, insbesondere Blockhöhe, Nonce, Timestamp und Epoch als u64, sofern ihre jeweiligen Standards nichts anderes bestimmen.

## 2. Normative Eigentümerschaft

Die monetäre Emissionsplanung bleibt ausschließlich in atc-algorithm::economics kanonisch definiert.

Downstream-Komponenten dürfen keine zweite Emissions-/Supply-Schedule definieren. Sie konsumieren die kanonischen Konstanten und Berechnungen.

Für die wirtschaftliche Wertkette gilt durchgehend u128 für Base Units:

Transaction.amount → Mempool → State → Consensus → Storage → Recovery

## 3. Konsensus-/Storage-Vertrag

Validator-Stake ist ein wirtschaftlicher Wert und wird deshalb als u128 repräsentiert.

Es sind keine lossy Konvertierungen u128 → u64 zulässig.

Persistente Validator-Snapshots müssen die vollständige u128-Base-Unit-Repräsentation erhalten. Änderungen am persistenten Encoding benötigen explizite Versions-/Migrationsbehandlung.

## 4. Evidence / Umsetzung

PR #55 im a-townchain-ecosystem operationalisiert die Policy an der betroffenen L1-Kette:

- Transaction Base-Unit Constructor akzeptiert u128
- Network-/Storage-Transaction-Decoding verwendet den u128-Pfad
- Validator-State/Consensus-Snapshots verwenden u128
- Validator-Snapshot-Wire-/Storage-Encoding verwendet 16 Byte
- Monetary supply cap konsumiert die kanonische u128-Konstante
- keine Rückkonvertierung wirtschaftlicher Werte auf u64

## 5. Erfolgskriterien

1. Registry-/Standardprüfung erfolgreich.
2. Alle betroffenen L1-CI-Gates kompilieren mit konsistenten u128-Economic-Types.
3. Transaction round-trip erhält Base Units bitgenau.
4. Validator snapshot round-trip erhält Stake bitgenau.
5. Restart/Recovery rekonstruiert identische wirtschaftliche Werte.
6. Keine lossy u128 → u64-Konversion in der kanonischen Economic-/Consensus-/Storage-Kette.
7. Emissionsschedule bleibt ausschließlich atc-algorithm::economics.

## 6. Governance

Dieser SCR ist ein **PROPOSED** Change Request. Er stellt die Policy zur Genehmigung vor; APPROVED/STABLE-Status entsteht ausschließlich über den in ATC-STD-000 definierten Governance-Prozess.
